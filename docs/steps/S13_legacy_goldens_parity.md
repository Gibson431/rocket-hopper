# S13: Legacy golden references and parity harness

**Depends on:** S11. **Effort:** 1 day. Can run in parallel with S12.

## Context

The hand-rolled simulator is the oracle for the port, and S22 deletes it. Before that, freeze what it
produces so later steps (and the deleted code's replacement) can be checked against stored data, and
build the comparison tools every porting step uses. Read `docs/CONVENTIONS.md` (logging schema),
`src/hopper/analysis/logger.py`, `src/hopper/scenario.py`, `tests/sim/test_hop_scenario.py`.

## Deliverables

### Golden data (`tests/golden/`, small parquet/JSON files, committed)
Generated by `scripts/make_goldens.py` from the *legacy* simulator. Record the config hash and git
commit in each file's metadata. Cases (open loop unless stated):
1. Free fall from 20 m, gravity only; and with aero and wind on.
2. Constant-thrust vertical burn, full propellant to a mid burn (mass, CoM and thrust history).
3. Constant gimbal and RCS roll: attitude and body-rate history through a 10 s burn.
4. Throttle step and gimbal step responses (actuator lag, gimbal rate limit).
5. Drop onto the pad from 0.5 m: settle height, peak foot force, rebound, then a tilted drop.
6. Sliding on the pad with initial horizontal speed (friction).
7. Closed loop: `hop_nominal` with perfect state, seed 0 (key metrics: outcome, landing error,
   touchdown speeds, fuel) and the S11 Monte Carlo baselines table (outcome counts per provided
   scenario, 16 seeds each, plus `hop_dispersed` 100 seeds).

Cases 1-6 use fixed `OpenLoopController` schedules and need no controller.

### Parity harness (`src/hopper/analysis/parity.py`)
- `compare_logs(reference, candidate, columns, rtol, atol) -> ParityReport` (max abs/rel error per
  column, time of worst error); both logs are in the S06 schema and are resampled to common times.
- `assert_parity(report, tolerances)` with a readable failure message.
- `metrics_close(a, b, tol)` for closed-loop summary metrics (S11 `HopSummary` fields).

## Tests (`tests/analysis/test_parity.py`, `tests/golden/test_goldens.py`)

- Harness: identical logs give zero error; a perturbed column is reported with the right size and time;
  differing time grids are resampled; missing columns raise.
- Goldens regenerate from the legacy sim with identical **data** (compare the DataFrames, not file
  bytes: the metadata holds the git commit, which changes), and the stored files load with the
  expected columns and metadata.
- The legacy sim passes `assert_parity` against its own goldens at `rtol = 1e-9, atol = 1e-12`
  (not zero: LAPACK/BLAS results differ across CPUs and CI runners), so S22 can delete it and keep
  this test as the regression for whatever replaces it. Closed-loop discrete metrics (outcome) must
  match exactly.

## Definition of done

- Goldens and generator script committed; the files total well under 5 MB.
- Tests pass; ruff clean. Progress tracker updated per `docs/AGENT_START.md`; note the golden file
  list and how to regenerate them.
